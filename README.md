# mscr

로컬 단일 사용자용 KRX 주식·ETF 스크리너, 종목 차트, 포트폴리오 평가 도구입니다. 데이터는 일봉 EOD 기준이며 주문·실시간 시세·백테스트·증권사 API 연동은 제공하지 않습니다.

## 설치

요구사항: Python 3.12+, [uv](https://docs.astral.sh/uv/), [Bun](https://bun.sh/), 인터넷 연결.

```bash
uv sync
cd frontend
bun install
bun run build
cd ..
```

## 최초 데이터 수집

```bash
uv run mscr ingest
```

기본값은 최근 400일(캘린더)입니다. 수집은 날짜별로 직렬·지연·재시도로 진행됩니다. 중단 후 같은 명령을 실행하면 `ok` 또는 `holiday`로 기록된 날짜는 건너뛰고 실패하거나 아직 수집하지 않은 날짜를 재시도합니다.

ingest 없이 KRX가 실제로 발표한 최신 거래일만 확인하려면:

```bash
uv run mscr krx-latest
```

`--days`는 새로 수집할 거래일 수가 아니라 확인할 최근 캘린더 범위입니다. KRX가 발표한 최신 거래일부터 거슬러 올라간 캘린더 N일 범위이며(`--days 1`이면 최신 거래일 하루만), 이미 `ok`/`holiday`로 기록된 날짜는 그중에서도 건너뜁니다. 예를 들어 최근 일주일만 확인하려면 다음과 같이 실행합니다.

```bash
uv run mscr ingest --days 7
```

매일 자동 실행할 때는 `--days 7`을 권장합니다. 며칠간 실행하지 않았다면 더 넓은 범위로 보완합니다.

```bash
uv run mscr ingest --days 30
```

기존 날짜도 강제로 다시 요청하려면 `--force`를 사용합니다. 지표는 스크린 실행 시 일봉에서 동적으로 계산되므로 별도 사전 계산 명령은 없습니다.

```bash
uv run mscr ingest --days 1 --force
```

KRX Open API가 아직 최신 거래일 데이터를 게시하지 않았다면(공표 지연), FinanceDataReader를 대체 소스로 써서 주식 종목만 우선 채울 수 있습니다. 전종목 시세를 한 번의 호출로 받아오되 기준 종목(삼성전자) 종가로 실제 거래일을 대조 확인하며, 이미 알려진 종목(유니버스에 등록된 주식)에만 적용됩니다. ETF는 이 소스로 필요한 시가·고가·저가를 제공하지 않아 지원하지 않습니다.

```bash
uv run mscr ingest --source fdr
```

KRX Open API와 FinanceDataReader 모두 특정 거래일의 데이터가 비어 있다면(신규 상장 종목 지연 반영, 부분 장애 등), alpha-square(alphasquare.co.kr)를 최후 폴백으로 쓸 수 있습니다. 전종목을 한 번에 반환하는 API가 없어 로컬에 이미 저장된 유니버스(`instruments` 테이블)의 종목을 하나씩 순회하며 조회하지만, 종목당 날짜 구간은 한 번에 받아올 수 있어 다른 소스와 동일하게 `--days`로 수집 기간을 지정합니다. 기준일은 로컬에 저장된 최신 거래일이 아니라 오늘 날짜입니다 — KRX가 아직 오늘자를 게시하지 않아 로컬 최신일이 뒤처진 상태가 바로 이 소스를 쓰는 상황이기 때문입니다. `--days N`은 오늘을 포함해 캘린더 N일을 거슬러 올라간 창입니다(`--days 1`이면 오늘 하루만). 이미 수집 완료로 기록된 거래일은 건너뛰고 빈 날짜만 채우므로, 평소에는 최근 며칠만 재조회하게 됩니다.

```bash
uv run mscr ingest --source alphasquare --days 7
```

종목 목록은 별도로 관리하지 않고 `instruments` 테이블(krx 소스로 채워짐)을 그대로 읽으므로, 이 소스를 쓰기 전에 KRX로 최소 한 번은 ingest해 유니버스를 채워둬야 합니다. 신규 상장 종목도 이 테이블이 갱신돼야 반영됩니다. 종목코드 → alpha-square 내부 ID 매핑은 `alphasquare_ticker_map`에 캐시해 재조회를 피합니다.

종목별로 개별 요청을 보내므로 요청 사이 지연도 아래 "수집 요청 간격(초)" 설정(`request_delay_sec`, 기본 0.3초)을 그대로 씁니다. 처음 보는 종목은 상세 조회 1회 + 시세 조회 1회, 매핑이 캐시된 종목은 시세 조회 1회만 호출합니다. 전종목처럼 큰 유니버스에 돌리면 시간이 오래 걸릴 수 있으니, 소수 종목이나 짧은 기간의 공백을 메우는 최후 폴백으로만 사용하세요.

alpha-square 캔들 API는 거래대금(`value`)을 제공하지 않아 종가×거래량으로 근사합니다. 스크리너 프리셋 상당수가 유동성 필터로 `value`를 쓰므로, 이 소스로 채운 날짜는 실제 거래대금과 오차가 있을 수 있습니다. 이후 KRX가 해당 거래일 데이터를 정식 게시하면 `mscr ingest --source krx --days N --force`로 덮어써서 정확한 값으로 교체하는 것을 권장합니다.

### KRX Open API 인증

KRX Open API를 사용하려면 인증키 발급뿐 아니라 다음 5개 API의 **서비스 이용 신청 및 승인**이 필요합니다.

- `stk_bydd_trd`: 유가증권 일별매매정보
- `ksq_bydd_trd`: 코스닥 일별매매정보
- `stk_isu_base_info`: 유가증권 종목기본정보
- `ksq_isu_base_info`: 코스닥 종목기본정보
- `etf_bydd_trd`: ETF 일별매매정보

인증키는 KRX Open API 사이트에서 발급합니다.

```bash
export KRX_OPENAPI_KEY='발급받은 AUTH_KEY'
uv run mscr ingest --days 1
```

Open API 요청에서 `AUTH_KEY`는 HTTP 헤더로, `basDd`는 `YYYYMMDD` 형식의 요청 파라미터로 전달됩니다. API 키는 SQLite나 프로젝트 파일에 저장하지 않습니다.

구형 웹 로그인 방식도 호환용으로 남아 있습니다. Open API 키가 없을 때만 사용됩니다.

```bash
export KRX_ID='아이디'
export KRX_PW='비밀번호'
uv run mscr ingest
```

### 사용자 지표

상단의 `지표 관리` 탭에서 사용자 지표를 추가·수정·삭제할 수 있습니다. 키는 영문 소문자로 시작하고 소문자·숫자·밑줄만 씁니다(접두어 규칙 없음). 기간과 계수는 수식에 고정하지 않고 이름 있는 파라미터로 정의한 뒤, 스크린 수식에서 위치 인자로 전달합니다.

```text
키: ma_gap
파라미터: period (기본 20, 최소 1, 최대 500, 정수)
정의 수식: close / sma(close, period) - 1
호출 수식: ma_gap(60) > 0.1
```

키가 내장 이름과 겹치면 저장이 거부됩니다. 사용자 지표는 수식 평가 시 내장 함수보다 먼저 조회되므로, 겹치면 내장을 조용히 가로채기 때문입니다. `and`·`or`·`not`처럼 수식 문법에 쓰이는 이름도 거부됩니다(파싱이 안 되어 저장해도 쓸 수 없습니다).

```text
내장 이름은 덮어쓸 수 없습니다: sma
수식 문법에 쓰이는 이름은 지표 키로 쓸 수 없습니다: and
```

정의 수식은 **스크린 수식과 똑같은 이름을 볼 수 있습니다.** 시세 시리즈(`open`·`high`·`low`·`close`·`volume`·`value`)뿐 아니라 스냅샷 값(`change_pct`·`market_cap`·`shares`·`per`·`pbr`·`eps`·`bps`·`div`·`bars_available`·`halted`·`price_jump_flag`)과 다른 사용자 지표도 씁니다.

```text
키: gap_vs_change
정의 수식: ma_gap(period) - change_pct / 100
```

사용자 지표끼리 겹쳐 호출할 수 있지만 순환 참조는 저장 시점에 경로와 함께 거부합니다.

```text
사용자 지표가 순환 참조합니다: ma_gap → gap_vs_change → ma_gap
```

호출된 지표는 호출한 지표의 파라미터를 볼 수 없습니다. 각 정의는 시세·스냅샷 값과 자기 파라미터만 보는 독립된 범위입니다.

내장 지표도 `ma20`, `rsi14` 같은 고정 별칭 없이 파라미터형 함수로 사용합니다. 지원 함수는 `sma`, `ema`, `rsi`, `returns`, `volume_ratio`, `historical_volatility`, `atr`, `rolling_max`, `rolling_min`, `crosses_above`, `crosses_below`, `abs`입니다.

스크리너 조건과 정렬은 각각 수식으로 작성합니다. 비교식은 `and`, `or`, `not`으로 조합할 수 있으며 모든 기간은 호출부에서 선택합니다.

```text
조건: close > sma(close, 35) and rsi(close, 9) <= 30
정렬: returns(close, 90)
```

모든 수식 입력창(스크린 조건·정렬, 지표 정의)에는 자동완성이 붙습니다. 이름 일부를 입력하면 시세 시리즈·스냅샷 값·내장 함수·활성 사용자 지표·논리 연산자 후보가 뜨고, `↑`·`↓`로 이동, `Enter` 또는 `Tab`으로 삽입, `Esc`로 닫습니다. 함수 후보를 고르면 여는 괄호까지 입력됩니다. 지표 정의 화면에서는 그 지표의 파라미터 이름도 후보에 포함되고, 편집 중인 지표 자신은 순환 참조가 되므로 후보에서 빠집니다. 후보 목록은 개수를 자르지 않고 넘치면 스크롤됩니다.

### 프리셋 관리

스크리너 상단 `PRESETS`에서 조건 세트를 관리합니다. 목록에서 고르고 `불러오기`를 누르면 유니버스·조건 수식·정렬·상한이 화면에 채워집니다.

- `새로 저장`: 이름 칸의 이름으로 현재 조건을 저장합니다. 같은 이름이 있으면 덮어쓸지 확인합니다.
- `선택 갱신`: 선택한 프리셋을 현재 조건으로 갱신하며, 이름 칸을 고치면 이름도 함께 변경됩니다. 다른 프리셋과 이름이 겹치면 거부됩니다.
- `삭제`: 선택한 프리셋을 확인 후 삭제합니다.

저장 시 조건·정렬 수식을 서버가 검증하므로 실행 불가능한 프리셋은 저장되지 않습니다. 프리셋은 `~/.mscr/mscr.db`의 `screens` 테이블에 저장되고, 기본 프리셋 8종은 최초 수집 시 자동 등록됩니다.

그중 `3R 목표 후보`는 손절폭의 3배(3R) 목표에 도달할 확률을 실제 일봉으로 측정해 만든 프리셋입니다. 조건은 20일 평균 거래대금 30억 초과·60일 고점 대비 4% 이내·`sma(close,60) > sma(close,120)` 세 가지뿐이고, 실제 선택은 `atr(high,low,close,14) / close` **오름차순 상한 5**가 합니다. ATR% 절대 수준이 3R 도달 확률을 지배하기 때문입니다(향후 60거래일 최대상승이 최저 십분위 7.60·ATR, 최고 십분위 3.56·ATR). 임계값이 아니라 정렬로 뽑으므로 시장 변동성이 올라간 국면에서도 후보가 마르지 않습니다. `3R 목표 후보 (저변동성 고정)`은 같은 조건에 `atr/close < 0.03`과 20/60일 실현변동성 비율 0.9~1.45 밴드를 더한 고정 임계 버전이며, 조용한 국면에서만 후보가 나옵니다.

측정 조건은 `자동 트레이딩` 절의 도달 확률과 같습니다(진입 = 다음 봉 시가, 손절 = k·ATR(14), 목표 = 3×손절폭, 보유 60거래일, 동시 터치는 손절 우선). 2024-06~2026-06 신호일 75.6만 건 기준으로 손절폭 2·ATR일 때 유니버스 전체는 3R 도달 21.5%·기대값 −0.04R인데, 이 프리셋 상위 5종목은 도달 36.1%·기대값 +0.50R입니다(왕복비용 0.25%와 갭 체결 반영). 전·후반 기간 분할, 손절폭 1.5~3.0·ATR, 보유 30~90일에서 모두 부호가 유지되고 25개월 중 19개월이 초과수익 흑자입니다. 다만 표본이 20개월뿐이고 우선주를 제외하면 기대값이 +0.38R로 떨어지므로 프리셋은 우선주를 포함합니다.

같은 표본에서 목표를 3R에서 5R로 늘리면(손절 2·ATR 고정) 종목별 비중복 거래 기준 기대값이 +0.51R에서 +0.69R로 오르고 전·후반 모두 유지됩니다. 대신 목표 도달률이 35.5%에서 21.7%로 떨어지므로, 트레이딩 탭의 분할 익절(1차 3R 40%·2차 5R 30%·잔량 트레일링 8%)이 기대값 +0.64R로 월별 변동이 가장 작은 절충입니다.

`박스 조임 후보`는 `3R 목표 후보` 조건에 **20일 박스폭(고가 최대−저가 최소)이 종가의 3~8%**라는 조임 조건을 더한 저빈도 프리셋입니다. 하방이 박스 바닥으로 닫혀 있고 상방(60일 고점 3% 이내·정배열)이 열린 자리만 남기며, 임계를 12%→10%→8%로 조일수록 기대값이 단조 개선되어 임계 선택이 체리피킹이 아님을 확인했습니다. 같은 측정 조건에서 비중복 77건 기준: 손절을 **박스 바닥(20일 최저가 − 0.25·ATR)** 에 두고 목표를 리스크의 3배(1:3)로 잡으면 기대값 +0.97R·도달 39.0%·손절 39.0%(평균 리스크는 진입가의 약 4.8%), 보수적으로 1:2면 +0.79R·도달 55.8%입니다. 2·ATR 손절도 기대값은 동급(+0.97R)이지만 손절당하는 비율이 45.5%로 높고 흑자월이 12/19로 고르지 못합니다. 조건 분해(고점근접·추세 각각 제거), 우선주 제외(+0.88R), 리스크 크기 구간별, 보유 30/60/90일에서 모두 양의 기대값이 유지됩니다. 주의: 표본이 77건으로 작고, 후보는 일평균 2.3개·후보가 있는 날이 62%뿐이며 변동성이 오른 국면에서는 수개월간 후보가 없을 수 있습니다(2026-08은 0건). 박스폭 하한 3%는 리스크가 진입가의 1~2%까지 좁아져 호가단위·비용 대비 퇴화하는 사례를 막는 가드입니다.

## 실행

```bash
uv run mscr serve
```

기본 주소는 <http://127.0.0.1:8765>입니다. 브라우저를 열지 않으려면 `uv run mscr serve --no-open`을 사용합니다.

화면은 스크리너·종목 상세·포트폴리오·트레이딩·지표 관리·설정 여섯 탭으로 구성됩니다. 스크리너에서 boolean 수식을 실행하고 행을 선택하면 수정주가 차트와 동적 지표가 표시됩니다. 포트폴리오 거래 원장은 화면에서 입력하며 SQLite에 저장됩니다.

## 설정

`설정` 탭에서 KRX 수집과 KIS 브로커 인증, 공통 옵션을 모두 관리합니다. 값은 `~/.mscr/`에 권한 `0600` 파일로 저장되고 SQLite에는 넣지 않습니다. **환경변수가 있으면 저장값보다 우선**하며, 화면과 CLI가 `source`(env/file)를 표시합니다.

| 항목 | 저장 파일 | 환경변수 | CLI |
|---|---|---|---|
| KRX Open API 키 | `krx_credentials.json` | `KRX_OPENAPI_KEY` | `mscr config krx --openapi-key …` |
| KRX 아이디·비밀번호(구형 웹) | `krx_credentials.json` | `KRX_ID`, `KRX_PW` | `mscr config krx --id … --pw …` |
| KIS 앱키·앱시크릿·계좌·환경 | `kis_credentials.json` | `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCOUNT`, `KIS_ENV` | `mscr trade login` |
| 수집 요청 간격(초) | `settings.json` | `MSCR_REQUEST_DELAY_SEC` | `mscr config delay 1.2` |

```bash
uv run mscr config show        # 해석된 인증·간격과 각 출처
uv run mscr config krx-clear   # 저장된 KRX 자격증명 삭제
uv run mscr trade logout       # 저장된 KIS 자격증명 삭제
```

설정 탭 하단의 `환경 정보`는 `MSCR_HOME`, DB 경로, 스키마 버전, 기준일, 일봉 행 수, 종목 수, 최근 수집 시각을 읽기 전용으로 보여줍니다. KRX 자격증명은 저장 파일이 있으면 환경변수가 우선 적용 중이어도 `삭제`로 지울 수 있습니다.

## 자동 트레이딩 (KIS)

`트레이딩` 탭에서 트레이딩 계획을 세우면 한국투자증권(KIS) Open API로 실제 주문을 냅니다. 인증은 위 `설정` 탭 또는 환경변수로 지정합니다.

인증 설정은 위 [설정](#설정) 절을 참고하세요. 화면(`설정` → `브로커 인증`), `mscr trade login`/`logout`, 환경변수 세 경로 모두 지원하며 환경변수가 우선입니다.

계획은 종목·방향·수량·주문유형(지정가/시장가)과 돌파 매매 조건(진입가·손절가·1차/2차 익절가+비율·3차 트레일링 스탑)으로 정의합니다. 종목·진입가·손절가·익절가는 스크리너나 차트로 직접 정한 값을 그대로 입력합니다. 최신 일봉의 고가/저가가 각 기준가를 건드리면 다음 단계로 진행합니다.

```text
종목: 005930 / 매수 / 10주 / 지정가 71,000원
진입가 69,000원(돌파) / 손절가 65,000원(이탈 시 즉시 전량 청산)
1차 익절 75,000원(40%) / 2차 익절 82,000원(30%) / 3차 트레일링 스탑 5%
```

진행 순서는 하나의 계획 안에서 순차적으로만 진행됩니다: 진입 → (손절 또는 1차 익절) → (손절 또는 2차 익절) → (손절 또는 트레일링 스탑 청산). 손절·1차·2차·트레일링 청산은 모두 시장가로 즉시 나갑니다. 1차·2차 비율의 합은 1보다 작아야 하며, 남은 수량이 3차 트레일링 대상입니다. 트레일링 기준가는 2차 익절이 체결된 날 이후의 최고가(매도 계획은 최저가)이며, 거기서 트레일링 비율만큼 되돌리면 잔량을 전량 청산합니다.

### 계획 자동 생성

종목·진입가와 **최대 투자 금액·최대 손실 금액**만 넣으면 나머지 필드(수량·손절가·1차/2차 익절가와 비율·트레일링 비율)를 역산해 후보를 제시합니다. 종목과 진입가는 스크리너·차트로 직접 정한 값을 그대로 씁니다.

```text
종목 005930 / 매수 / 진입가 257,000원
최대 투자 금액 10,000,000원 / 최대 손실 금액 300,000원
```

종목·진입가가 정해지면 남는 자유도는 손절폭 하나뿐입니다. 손절폭을 좁히면 같은 손실 한도로 수량이 늘고 목표가도 가까워지지만 손절 확률이 올라갑니다. 그래서 손절폭을 ATR(14) 배수 6가지로 펼친 후보 표를 냅니다.

| 손절폭 | 손절가 | 수량 | 실투자 | 최대손실 | 분할 | 1차 목표 | 2차 목표 | 도달1 | 도달2 |
|---|---|---|---|---|---|---|---|---|---|
| 1.0·ATR | 238,500 | 16 | 4,112,000 | 296,000 | 6/5/5 | 294,000 | 331,000 | 69% | 49% |
| 1.5·ATR | 229,000 | 10 | 2,570,000 | 280,000 | 4/3/3 | 313,000 | 369,000 | 58% | 36% |
| 3.0·ATR | 200,500 | 5 | 1,285,000 | 282,500 | 2/2/1 | 370,000 | 483,000 | 36% | 17% |

- 수량은 `min(최대 투자 금액 ÷ 진입가, 최대 손실 금액 ÷ 손절폭)`의 정수 부분입니다. 어느 제약이 수량을 결정했는지(`binding`)를 화면이 명시합니다. 손실 한도가 걸리면 투자 한도는 사실상 제약이 되지 않습니다.
- 분할 수량은 정수로 배분되고 합이 계획 수량과 정확히 일치합니다. 비율은 그 정수에서 역산한 값입니다.
- 손절가·목표가는 KRX 호가가격단위(2023-01-25 개정, ETF는 5원)에 맞춰 정렬됩니다. 손절가는 항상 진입가 쪽으로 정렬하므로 정렬 때문에 최대 손실 금액을 넘지 않습니다.
- 도달 확률은 전 종목 일봉을 ATR 단위로 정규화해 모은 무조건 excursion 분포입니다(진입 후 60거래일 내 해당 배수 도달 비율). 특정 조건에 맞춘 값이 아니므로 과최적화되지 않습니다.
- `기준선 기대값`은 **진입 근거가 없을 때**의 과거 통계이며 예측이 아닙니다. 대개 음수입니다. 종목과 진입가를 직접 정하는 이상 기대이익은 그 판단에서 나오고, 자동 생성이 하는 일은 제약을 지키는 것·도달 가능한 목표를 잡는 것·그 기준선을 알려주는 것까지입니다.
- 권장 후보는 예측이 아니라 명시된 규칙입니다: ① 손실 한도를 90% 이상 소진하고 ② 2차 목표 도달 확률이 33% 이상 남아 있는 후보 중 ③ 손절폭이 가장 넓은 것. ②는 트레일링 잔량이 가동될 여지를, ③은 종목 자체 변동성에 손절이 털리는 것을 각각 막습니다.

제약이 너무 빡빡해 3분할이 성립하지 않으면 필요한 최소 금액을 알려주고 거부합니다.

```text
주어진 제약으로는 계획을 만들 수 없습니다 — 최소 3주를 담으려면 최대 손실 금액이 447,942원 이상이어야 합니다
```

**최대 손실 금액은 보장이 아닙니다.** 일봉 EOD 평가 구조라 갭 하락 시 손절가를 크게 밑도는 시가에 시장가로 청산됩니다. 또 한도는 계획 1건 기준이므로 계획 여러 개가 동시에 열리면 합산 손실이 한도를 넘습니다. 이 두 가지는 화면에도 항상 표시됩니다.

실행 경로는 두 가지입니다.

```bash
uv run mscr trade plans        # 계획과 현재 단계·다음 동작
uv run mscr trade run          # 모의 실행(dry-run): 주문 없이 기록만
uv run mscr trade run --live   # 실주문 전송 (확인 프롬프트)
uv run mscr trade sync         # 체결 조회 후 기록·포트폴리오 반영
```

안전장치:

- 기본값은 dry-run이며, 실주문은 CLI `--live`(확인 프롬프트) 또는 화면의 `실주문 실행`(계좌·환경·대상 건수를 명시한 재확인)으로만 전송됩니다. 브로커 환경변수가 없으면 실주문 버튼과 API가 모두 막힙니다.
- 청산(손절·1차·2차·트레일링) 주문은 실주문 모드에서 실제 보유 수량을 초과하면 주문하지 않고 `skipped`로 기록합니다. 모의 실행은 계획 자체의 수량 계산만 사용하므로 이 제한을 받지 않습니다.
- 종목 일봉이 최신 수집일보다 오래되면 주문하지 않습니다(정지·상장폐지 종목 오주문 방지).
- 이미 시도한 단계(진입/손절/1차/2차/트레일링)는 성공·모의·접수 상태면 다시 시도하지 않습니다. 거부·실패한 시도는 다음 실행에서 재시도됩니다.

모든 시도는 `broker_orders` 테이블에 남습니다(`dry_run`·`submitted`·`partial`·`filled`·`rejected`·`failed`·`skipped`). `mscr trade sync`(또는 화면의 `체결 동기화`)가 체결을 확인하면 `trades` 테이블에 거래를 한 번만 기록하고, 포트폴리오 평가와 실현손익에 즉시 반영됩니다. 수수료·세금은 KIS 체결 조회에 포함되지 않으므로 0으로 기록되며 필요하면 포트폴리오 원장에서 수정하세요.

## 상태 확인

```bash
uv run mscr doctor
```

기본 데이터베이스는 `~/.mscr/mscr.db`입니다. 실험용 DB를 분리하려면 `MSCR_HOME`을 지정합니다.

```bash
MSCR_HOME=/tmp/mscr-test uv run mscr ingest --days 30
MSCR_HOME=/tmp/mscr-test uv run mscr doctor
```

`MSCR_REQUEST_DELAY_SEC`로 요청 간격을 조정할 수 있습니다. KRX/Naver 응답이 반복적으로 실패하면 1.0 이상으로 올리고 `--days`를 여러 번 나누어 실행하세요.
